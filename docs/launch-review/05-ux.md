# UX Review — SolWhisper Public Launch

Static, code-based reconstruction of the experience (no app launches). Goal per the brief:
"really clear and easy to understand for **anyone**," including non-technical users. Every
BLOCKER and the concrete MAJORs were re-verified against code by the synthesizer.

## First-run golden path (a): install → first dictation into Notes

1. **DMG → Applications → open.** Unsigned build → Gatekeeper "cannot verify" wall. User must know
   right-click → Open. Nothing explains it. First stall; a meaningful fraction of non-technical users
   stop here. (Root cause = the notarization blocker, `03-security.md` B1.)
2. **Launch: no Dock icon, no window intro — then 3 things fire at once:** onboarding window +
   Accessibility OS prompt + Speech OS prompt (`AppDelegate.swift:143-144`), then 1.5s later a
   deprecated `NSUserNotification` "SolWhisper needs permissions" whose "Open Settings" button does
   nothing. Prompt storm + false alarm before the user has done anything.
3. **Welcome teaches the wrong shortcut** (BLOCKER, verified): copy says `⌥⌘R`
   (`OnboardingView.swift:191`) but the registered default is `⌃⌥⌘R` (mask 11, `AppDelegate.swift:72`).
   The first thing the app teaches fails when tried.
4. **"AI polish" step**: toggle defaults ON and **Continue is disabled until an OpenRouter key is
   entered** (`OnboardingView.swift:41`). "Skip" jumps to hotkeys, **skips the Meetings step**
   (`:166`), and leaves polish enabled with no key → every later dictation fires a doomed LLM call.
5. **"You're ready!"** never says the app lives in the menu bar. Window closes; if the (mistaught)
   hotkey fails, the app has effectively vanished (no Dock icon; re-onboarding is buried in
   Settings → Debug). Closing the window with X never sets `hasCompletedOnboarding` → onboarding
   reappears every launch.
6. **First dictation:** on mic **denial**, the overlay pill sits "listening" forever with no error,
   and pressing the hotkey again restarts instead of stopping — dead end (`TranscriptionController.swift:275`).
7. **Paste:** if Accessibility/Automation aren't granted, all paste methods fail, text lands only on
   the clipboard, and the "press ⌘V" notice goes to the **debug log, not the user**
   (`PasteManager.swift:92`). The golden path dies silently — "I dictated and nothing happened."

Total OS dialogs in a full first session: **7** (Gatekeeper, Accessibility, Speech, Mic, Automation,
Screen Recording, Calendar).

## First-run golden path (b): first meeting → find + read transcript

- Feature discoverable only via the menu-bar "Record meeting"; the one-time consent alert is well
  written (`PrivacyDisclaimer.swift`).
- **Screen Recording missing → records mic-only with no warning** (`MeetingController.swift:156`) —
  a 60-min call captured as one-sided. Silent data loss.
- **First meeting silently downloads the ~74 MB WhisperKit model** with a 0% step and no label; the
  import window has the right copy ("Downloading… ~74 MB") but the live pipeline doesn't reuse it.
  **Offline, the transcription error is swallowed to `[]`** (`MeetingController.swift:585-595`) → an
  empty transcript with no retry hint.
- **Summary silently absent on fresh install** (MAJOR, verified): the pipeline reads
  `UserDefaults.bool("meetingsAutoSummarize")` = false-when-unset (`MeetingController.swift:550`),
  while the settings toggle shows ON via `@AppStorage(... = true)` (`MeetingSettingsView.swift:5`).
  The marquee "auto-summary" promise is quietly broken until the user toggles it off and on.
- **Transcript colors:** `[Me]` badge is hardcoded white (`MeetingDetailView.swift:1816`) in a
  window that follows system appearance → invisible in light mode; the speaker palette is tuned for
  dark backgrounds.

## BLOCKER (fix before public launch — first-session breakers)

All verified against code:

1. **Paste failure is invisible.** `PasteManager.swift:92` logs to debug only. Surface via the
   existing overlay banner: "On your clipboard — press ⌘V. (Enable SolWhisper in System Settings →
   Privacy → Accessibility to auto-paste.)"
2. **Mic/speech denial = stuck "listening" pill, no error, no recovery.** `TranscriptionController.swift:275`.
   Call the existing `onAudioFailure?` with a System Settings deep-link.
3. **Screen-Recording missing → silent mic-only meeting.** `MeetingController.swift:156`. Alert before
   starting, offer "Record mic only / Open Settings / Cancel," mention the macOS app-restart quirk.
4. **Onboarding teaches the wrong shortcut** (`⌥⌘R` vs real `⌃⌥⌘R`). `OnboardingView.swift:191`; stale
   mask-10 literals also at `:24,:26` and `SettingsView.swift:321-323`. Render the live value; fix the
   literals to mask 11.
5. **First meeting: silent 74 MB download; offline = empty transcript, error swallowed.**
   `MeetingController.swift:585-595`. Add a "Downloading speech model (one-time, ~74 MB)" phase; on
   failure set the step to `.failed` with a retry message instead of writing `[]`.
6. **"STT Short" / "STT Meetings" as top-level Settings nav.** `SettingsView.swift:10-11`. Rename to
   "Dictation" / "Meetings"; sweep cross-references (e.g. `MeetingDetailView.swift:1628`).

## MAJOR (verified selection)

- **Auto-summarize default mismatch** (UI ON, pipeline reads OFF). Register `meetingsAutoSummarize: true`
  in the AppDelegate defaults block, or use the `object(forKey:) as? Bool ?? true` pattern already used
  for auto-clean. `MeetingController.swift:550`.
- **Polish enabled without a key → doomed LLM call every dictation; Skip doesn't disable it.**
  `TranscriptionController.swift:252`, `OnboardingView.swift:166`. Skip should set `enableLLMPolish=false`;
  resolver should return nil when the routed provider has no key.
- **Skip skips the Meetings step** (`:166` → `.hotkey`). Change to `.meetings`.
- **User never told the app lives in the menu bar; re-onboarding hidden in Debug.**
  `OnboardingView.swift:387-404`, `SettingsView.swift:486-491`. `openOnboardingFromMenu` (`AppDelegate.swift:862`)
  is dead code. Add "Setup Guide…" to the tray/Home; final step points at the menu bar.
- **Closing the onboarding window ≠ complete → reappears every launch.** `AppDelegate.swift:893-916`.
- **Global ESC (from any app) cancels and discards dictation.** `AppDelegate.swift:659-663`. At least
  flash "Dictation cancelled (Esc)" first.
- **English-only defaults, no language controls.** `AppleSpeechClient.swift:13` (hardcoded `en-US`),
  `WhisperKitClient.swift:200` (`base.en`). Non-English speakers get gibberish with no clue. Add a
  dictation language picker; label models "· English only."
- **Privacy overclaim:** "Audio never leaves your device" (`OnboardingView.swift:274`) /
  "on-device… privately" (`Info.plist`) but `requiresOnDeviceRecognition` is never set on
  `AppleSpeechClient`. Set it when supported, else soften the copy.
- **`[Me]` badge invisible in light mode; palette tuned for dark.** `MeetingDetailView.swift:1816`.
- **Zero `accessibilityLabel` in the entire app** (verified: 0 files). Icon-only overlay
  cancel/accept/pause and settings pencil/trash/eye buttons are unlabeled — a VoiceOver dead zone on the
  core loop of a dictation product. Start with the recording overlay.
- **Meeting "stop" affordance is a checkmark** (verified): `RecordingOverlayView.swift:207` is literally
  `phaseState.mode == .meeting ? "checkmark" : "checkmark"`. Use `"stop.fill"` in meeting mode.
- **Settings offers pickable options that do nothing** (Parakeet/streaming/FluidAudio "ships in v0.6…").
  `ModelsSettingsView.swift:44,58-63,72,78-83`. Remove or disable with "Coming soon" for launch.
- **Deepgram key in plaintext UserDefaults while onboarding implies Keychain.** (Cross-refs security H2.)
- **First-launch permission dialogs fire blind + the broken `NSUserNotification`.** Move Accessibility/Speech
  requests into explained onboarding steps; replace the notification with a Home permissions-health card
  with per-row deep links (the pattern already exists for Calendar in `PeopleSettingsView.swift:145-164`).
- **Empty states omit the primary action** (`MeetingListView.swift:134` says "Upload an audio file,"
  never "Record a meeting"). **Stale copy**: History pane says "Coming in v0.5" / "mode-A"
  (`TranscriptsRootView.swift:112,117`) on a 0.7.1 app.
- **Auto-fanout failures invisible** (`MeetingController.swift:729`) — user believes notes reached
  Obsidian/Kiros. Persist + surface last-send status (manual Send already does).

## Info.plist usage strings — verdict

Mostly good. Two fixes: `NSScreenCaptureUsageDescription` only mentions meetings but the same permission
powers Text Snap/Translate screen capture — say both. `NSAppleEventsUsageDescription` ("needs Apple
Events to paste") → plain: "…to press ⌘V for you so your words land in the app you were using."

## Top 10 UX fixes (ranked by first-session impact)

1. Make paste failure visible (overlay banner + Accessibility deep-link). `PasteManager.swift:92`.
2. Handle mic/speech denial with a System Settings deep-link, not a stuck pill. `TranscriptionController.swift:275`.
3. Fix the Welcome hotkey copy to the real default and purge stale mask-10 literals. `OnboardingView.swift:191`.
4. Warn before mic-only meetings when Screen Recording isn't effective. `MeetingController.swift:156`.
5. Register `meetingsAutoSummarize=true` so the first meeting actually summarizes. `AppDelegate.swift` defaults.
6. Rename Settings nav (Dictation/Meetings); kill "mode-A"/"Coming in v0.5"; move "Setup Guide" out of Debug.
7. Onboarding structural pass: Skip → meetings step + disables keyless polish; final step shows the menu-bar
   location; move Accessibility/Speech prompts into explained steps; treat window-close as completion.
8. Surface the one-time model download; fail loudly offline instead of an empty transcript. `MeetingController.swift:585`.
9. Fix light-mode transcript colors. `MeetingDetailView.swift:1816`.
10. Add `accessibilityLabel` to all icon-only controls, starting with the recording overlay.

**Cheap high-trust bonus:** broaden the screen-capture usage string, Title-Case the tray menu, move the
Deepgram key to Keychain.
